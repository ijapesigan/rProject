# How an rProject Project Works

Every project is an R project built from the rProject template: a CRAN
package, a manuscript, a library of references, a talk, or a container
image. This vignette describes how such a project is laid out, which
files `make` writes, and how a change travels from Overleaf to the
public repository. It is written for the user, for co-authors, and for
AI agents.

## Types

The type is a line in `.setup/scripts/project.R`, for example
`type <- "cran"`. Each type uses a few sets of template files
(`inst/template/<set>/`).

| type | sets | use |
|:---|:---|:---|
| rProject | common, package, cran, rproject | rProject itself |
| cran | common, package, cran | R packages (cran-*, devel-*) |
| man | common, package, man | manuscripts (man\*), which are R packages too |
| lib | common, lib | biblatex libraries (lib-\*) |
| talk | common, talk | talks |
| docker | docker | container images (docker-\*) |

## Folders

The standard folders, the types that have them, and what they are for
(`inst/template/folders.tsv`). Private folders stay on Overleaf and in
the private repository; they never go public. `make` creates the folders
marked “created” (with an empty `.gitignore`); the others appear when
they are needed. `make tree` lists the folders of a project and flags
the ones that are missing or not standard for its type.

| `.setup/data-raw/` | rProject, man |  | yes | shareable raw data |
| `.setup/data-process/` | rProject, man |  | yes | scripts that build `data/*.rda` from the raw data |

| `.setup/data-cache/` | rProject, man | yes |  | cached downloads and intermediate data |
| `.setup/bin/` | rProject, cran, man, lib, talk, docker |  |  | optional: R scripts run at `make project` (for example, to build a bespoke binary) |

Notes:

- `.setup/notes/` is private. Library projects keep the reference PDFs
  there.
- `.setup/bin/` is optional:
  [`Binary()`](https://github.com/ijapesigan/rProject/reference/Binary.md)
  runs its R scripts at `make project` (for example, to build a bespoke
  binary).
- Code coverage: to leave files out, put covr’s `.covrignore` at the
  project root and add it to `.Rbuildignore` (`ignore` in
  `.setup/scripts/project.R`).
- The naming rules for files in `R/`, `tests/testthat/`,
  `.setup/r-dependencies/`, and the test folders are in the R style
  guide (`.setup/latex/rProject-002-style-R.Rtex`).

## Template files

[`rProject::Template()`](https://github.com/ijapesigan/rProject/reference/Template.md)
(run by `make project` and `make template`) keeps the template files of
a project in step with rProject. Each file has a tier:

- **Tier 1, links.** Files that Overleaf or `make` needs (`Makefile`,
  `latexmkrc`, the LaTeX preamble, …). They are linked into the Overleaf
  project from rProject’s Overleaf project.
  [`Template()`](https://github.com/ijapesigan/rProject/reference/Template.md)
  never writes them; it lists those that differ as links to refresh.
- **Tier 2, written by `make`.** Everything else: the workflows, the
  make scripts, the Quarto pages, the folder skeleton.
  [`Template()`](https://github.com/ijapesigan/rProject/reference/Template.md)
  writes a file that is missing or differs (the template wins: change it
  in rProject). These files are not uploaded to Overleaf.

Workflows that only some projects run are in a catalog
(`inst/template/workflows/`). A project names the ones it runs in
`project.R`:

\
`workflows`` ``<-`` `[`c`](https://rdrr.io/r/base/c.html)`(``"docker-build-push-multi"``, ``"docker-build-push-daily-multi"``)`\
`workflow_daily`` ``<-`` ``"docs"`\
`workflow_title`` ``<-`` ``"Docker Build and Push Docs [multi] (Daily)"`\
`workflow_cron`` ``<-`` ``"30 3 * * *"`

The daily docker workflow is written as
`docker-build-push-daily-multi-<workflow_daily>.yml`, with its title and
cron filled in.

Files that leave the template are listed in `inst/template/removed.tsv`.
[`Template()`](https://github.com/ijapesigan/rProject/reference/Template.md)
deletes them (a folder only when nothing but `.gitignore` files is left
in it) and names them, so that they can be deleted in Overleaf too.

## From Overleaf to the public repository

1.  **Edit on Overleaf.** Overleaf is the main editor. Co-authors edit
    there. Agents edit a local clone; the user uploads the changed
    files.
2.  **Log.** Every change set (one Overleaf push) has a log in
    `.setup/logs/YYYY-MM-DD-<topic>.md` (`make log`), with the commit
    message and the files to upload or delete.
3.  **O2G.** The user pushes from Overleaf to the private GitHub
    repository. `make verify RECORD=TRUE` checks that the private
    repository matches the local clone and records the push in the log
    and in `.setup/logs/index.md`.
4.  **PUB.** `make all` builds and checks everything; `make auto` checks
    the public export (no private files, nothing over 50 MB, no tokens)
    and pushes to the public repository.

## Make targets

| Target | Does |
|----|----|
| `make project` | settings, template files, AI files |
| `make all` | build, docs, LaTeX, pkgdown, Quarto, coverage |
| `make lint` | style and lint the R code; report Overleaf limits |
| `make sizecheck` | check Overleaf limits |
| `make spec TOPIC=<topic>` | start a spec for a change set |
| `make log TOPIC=<topic> SUMMARY="..."` | write the change-set log |
| `make verify RECORD=TRUE` | verify and record a push from Overleaf |
| `make auto` | publish to the public repository |
| `make tree` | the project’s folders and what each is for |
| `make template` | write the template files only |
| `make latex`, `make pdf` | knit and compile the LaTeX sources |

R runs only inside an Apptainer image:
`apptainer exec <image> make <target>`.

## Keywords

Short messages from the user to an AI agent:

| Keyword | Means |
|----|----|
| “O2G” | the user pushed from Overleaf to GitHub: verify and record the push |
| “PUB” | the user ran `make all` and `make auto`: check the public repository and its CI |
| “build docs” | publish the docker images in order and rebuild the `docs` images |
| “EX” | the user is leaving: update `.setup/notes/claude.txt` and the handoff |
| “handoff” | rewrite `.setup/ai/handoff.md` without leaving |

The private files that agents read (`AGENTS.md`, `.setup/ai/`) are
written by
[`rProject::AI()`](https://github.com/ijapesigan/rProject/reference/AI.md).
